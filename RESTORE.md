**Check a backup is genuine** (re-hashes every archive and the whole chain):
```bash
python3 scripts/backup_meensha.py --verify        # prints OK/FAIL per backup, then CHAIN VALID/INVALID
```
Any edit, deletion or swap of a past backup breaks the chain and shows FAIL.

## 3. Restore the database (structure first, then data)
1. Create/choose the Supabase project and link it: `supabase link --project-ref <ref>`.
2. Structure: apply `setup/schema_combined.sql`, then each `setup/add_*.sql`, then `supabase/migrations/*.sql` in filename order. **The authoritative record of what was actually live** is inside the backup (`extras/columns.json`, `policies.json`, `functions.json`, `cron_jobs.json`): compare against it, because some migrations were files-only and not applied (see TODO "Data quality / unapplied migrations").
3. Data (dry run first, nothing is written without `--apply`):
```bash
python3 scripts/restore_meensha.py --list
python3 scripts/restore_meensha.py --stamp <STAMP> --region all           # dry run
python3 scripts/restore_meensha.py --stamp <STAMP> --region india   --apply
python3 scripts/restore_meensha.py --stamp <STAMP> --region australia --apply
python3 scripts/restore_meensha.py --stamp <STAMP> --region all --apply --storage   # shared tables + files
```
`india`/`australia` restore only that region's rows (tables with a `region` column, and `_au` tables for Australia). Shared tables (inventory, settings, etc.) restore only with `--region all`. Nothing is ever deleted; existing rows are left as they are.

## 6. Telegram webhooks (one per bot)
```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://<ref>.supabase.co/functions/v1/<telegram-bot | telegram-bot-au | telegram-bot-monitor>" \
  -d "secret_token=<matching TELEGRAM_WEBHOOK_SECRET*>"
```
India = Shalini's bot (`telegram-bot`), Australia = `telegram-bot-au`, Monitor = `telegram-bot-monitor`. Allowed users are rows in `telegram_allowed_users` / `telegram_allowed_users_au` (restored with the data).

## 7. Scheduled jobs (pg_cron)
Apply each cron SQL: `setup/add_daily_health_check_cron.sql`, `add_pending_cost_digest_cron.sql`, `add_returns_pending_digest_cron.sql`, `add_saree_requests_cron.sql`, `add_todo_worker_digest_cron.sql`, `add_post_suggestion_nudge_cron.sql` (Mon/Thu 09:30 IST posting nudge), `add_session_autoclose_cron.sql` (closes idle bot sessions after 30 min), `add_social_actions_reminder_cron.sql` (08:30 IST daily social reminder until done). The activity-summary, auth-log, daily-summary (India/AU) jobs are recorded in the backup's `extras/cron_jobs.json`.
